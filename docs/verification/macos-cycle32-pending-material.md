# macOS cycle 32: exact pending material through ambiguous replies

The actual `VEXAppState.applyNativePSKCutover` now retains canonical candidate bytes separately from admission in `NativeAdmittedProfileStore.Candidate`. The signed envelope is reverified and rebuilt without DNS on each entry; exact source revision/owner, full prepared profile, account/install/session, helper object, private intent fingerprint and original VPN generation must match before any candidate resolution or helper RPC.

A lost commit reply plus temporarily unavailable authenticated receipt keeps both private metadata and memory material. A later exact root receipt can finish the original operation, including after same-process coordinator reconstruction, without another DNS resolution, staging write, replacement, commit or reconnect. Cached metadata alone is not admission. Missing material or changed policy/selection/routing is rejected before DNS/RPC. Cache-only retry also requires current material. A changed candidate-active or apparently-idle status hint cannot bypass retained intent reconciliation: exact scoped memory and authenticated root proof remain required. Exact material survives admission of its proven candidate; only successful cache/intent completion or confirmed source recovery/pre-mutation failure clears it. Other admitted source/session changes invalidate it, and stale completions cannot delete a newer revision. No raw config or new secret is persisted.

Frozen actual-app evaluator on original/current/rollback copies: 53 cases; original and rollback have eight failures, current zero. All previous 44 app cases remain. New cases cover lost reply/proof plus changed candidate DNS with same/fresh coordinator, missing material, different signed geometry, changed location/routing and confirmed recovery followed by a fresh attempt. Inert RPC/profile ports only: no installed helper/app, network, Keychain, APNs or production operations.

This is NOT full app-process restart recovery, cross-process owner adoption, OS-crash/power-loss proof or release acceptance. A source TODO keeps signed geometry/material reconciliation and explicitly authorized owner transfer pending. Developer ID/notarization and isolated installation/connect/update acceptance remain required.
